# 原創全彩電子寵物｜詳細驗收測試計畫

> 文件版本：1.1｜2026-11-05｜狀態：測試設計完成、**實作及測試尚未執行**  
> 需求來源：`PRD_Uni_Inspired_Virtual_Pet_v1.1.md`  
> 目的：把 Tamagotchi Uni 類型的原創遊戲系統拆成可執行、可重現、可追蹤至 Git commit 的驗收測試。

## 1. 驗收方法與記錄要求

- **P0**：M3 Mac MVP 放行前必須 100% PASS（Mac 適用項）；硬體專屬項不可冒稱已通過。Critical/High 缺陷 = 0。
- **P1**：M4 納入的系統全部 PASS，P0 回歸全部 PASS。臨時託管為候選功能，不納入則在 scope change log 說明。
- **P2**：M5 需附真實硬體與感測器測試記錄，模擬器測試不能代替實機量測。
- **P3**：M6 必須通過安全、回滾、離線、權限與資料保護驗證才能開放服務。
- **測試類型**：UT＝單元測試；IT＝整合測試；E2E＝模擬器端到端；FI＝故障注入；HW＝實機；SEC＝安全；UX＝使用性；PERF＝效能。
- **每筆證據必備欄位**：Test ID、AC ID、Git SHA、build/tag、OS/板卡與版本、資料 fixture、步驟、期待結果、實際結果、PASS/FAIL/BLOCKED、日誌或錄影 URI、issue URL。
- **禁止假通過**：尚未建置的功能填 `NOT RUN`，測試環境或授權不可用填 `BLOCKED`；只有附證據的結果才能填 `PASS`。

|---|---|---|

| FX-05 | 已有有效存檔與上一份備份 | 斷電／壞檔恢復 |
| FX-06 | 貨幣=9、售價=10、背包只剩 0 空位 | 商店交易失敗 |

## 3. P0 端到端驗收（Mac MVP）

### TC-P0-01｜首次進入遊戲
- **對應**：AC-INIT-01/02/04、AC-UI-01/03；FX-00；E2E。
- **Given** 無存檔、固定時鐘與 seed，啟動 240×240 Mac 模擬器。
- **When** 用三鍵選「新遊戲」並確認。
- **Then** ≤3 秒進入房間；寵物 ID 產生，數值 0..100；重新用同配置開始測試會得到相同初始數值；全部可見文案為繁體中文。
- **證據**：啟動畫面錄影、初始 SaveSnapshot、E2E log。

### TC-P0-02｜覆蓋舊進度的保護
- **對應**：AC-INIT-02/03；FX-05；E2E/IT。
- **Given** 已有有效存檔且已記下 checksum。
- **When** 選新遊戲、確認對話選「否」，再重啟。
- **Then** 仍載入原有寵物，原檔 checksum 與關鍵狀態不變；選「是」才可替換。
- **證據**：存檔雜湊比較、按鍵錄影。

### TC-P0-03｜三鍵導覽完整性
- **對應**：AC-INPUT-01/03/04、AC-DEV-02；FX-01；E2E。
- **Given** 選單含 10 項且巢狀深度至少 3 層。
- **When** 使用 A 切換 10 次、B 進入 3 層，再連按 C 返回。
- **Then** 焦點循環且不越界；每次 C 返回一層，最後回房間；遊戲需求數值未意外改變。
- **證據**：輸入事件順序、前後狀態 diff、錄影。

### TC-P0-04｜實體彈跳、長按、防重送
- **對應**：AC-INPUT-02/05/06、AC-CARE-03；FX-01；UT/IT。
- **Given** 輸入模擬器可注入 30ms 以下的彈跳與 600ms 的長按。
- **When** 注入 30ms 彈跳、600ms 長按，以及同一交易 ID 的 B 連按 5 次。
- **Then** 每次實際按壓最多一個短按；長按不附送短按；交易僅結算一次且背包只扣 1 個。
- **證據**：事件計數、transaction ledger、測試輸出。

### TC-P0-05｜完整照顧路徑
- **對應**：AC-CARE-01/04/05/06/07/08、AC-STAT-02/03/04；FX-01；E2E。
- **Given** 初始有食物，且精力允許玩耍。
- **When** 依序餵食、玩耍、清潔、休息、開狀態頁。
- **Then** 每個動作都有可見回饋與事件；飽足/心情/清潔/精力方向正確；六個需求可查看；C 可以返回。
- **證據**：逐步錄影與前後 state diff。

### TC-P0-06｜失敗的照顧不改變狀態
- **對應**：AC-CARE-02/08、AC-STAT-01、AC-HEALTH-04；FX-01（食物設為 0）；E2E/UT。
- **Given** 背包食物=0，另設可用藥品=0。
- **When** 嘗試餵食與治療。
- **Then** 顯示「沒有食物／沒有藥品」等明確原因；背包、需求、健康無變化；不播放成功回饋。
- **證據**：拒絕事件、存檔 diff、截圖。

### TC-P0-07｜六項需求與門檻無抖動
- **對應**：AC-STAT-01/05/06；FX-02；UT/IT。
- **Given** 六項需求接近 0、25、35、100 邊界。
- **When** 快轉 24h，執行 10,000 次隨機合法命令，反覆跨越警示門檻。
- **Then** 所有值始終 0..100；≤25 進入警示、≥35 才退出；固定 seed 結果一致，警示不因單點波動每幀切換。
- **證據**：property test 報告、事件時間序列。

### TC-P0-08｜晝夜作息與睡眠
- **對應**：AC-TIME-02/06、AC-CARE-06；FX-03；IT/E2E。
- **Given** 設定 UTC+08:00、睡眠規則與低精力。
- **When** 快轉跨夜、切換到睡眠期並嘗試被禁止的行為。
- **Then** 畫面與作息規則一致；睡眠中的禁用操作明確顯示原因；沒有負精力或無限睡眠。
- **證據**：時鐘與行為日誌、夜間畫面錄影。

### TC-P0-09｜離線時間快轉與回撥
- **對應**：AC-TIME-01/03/04/05；FX-05；UT/IT。
- **Given** 存檔最後時間 T，預設一次離線推進上限 48h（待平衡定案）。
- **When** 分別載入 T+6h、T+7d 與 T−4h，另用 Debug 快轉 7d。
- **Then** 正向時間按規則推進；7d 不超過上限；回撥時間進度為 0 並留下異常原因；作業系統時鐘不變。
- **證據**：時間差計算 log、SaveSnapshot、測試報告。

### TC-P0-10｜自主 AI 的需求優先
- **對應**：AC-AI-01/02/03/07；FX-02、FX-03；UT。
- **Given** 固定個性、需求、時鐘與 100 個種子。
- **When** 比較正常與飢餓／低精力情境中的 100 次決策。
- **Then** 飢餓時 `seek_food` 頻率高於正常、低精力時 `rest/sleep` 優先；同種子結果完全一致；每次有 `reason`。
- **證據**：策略決策比較表、測試輸出。

### TC-P0-11｜自主 AI 的穩定性與中斷
- **對應**：AC-AI-04/05/06/08；FX-01；IT/E2E。
- **Given** 正常需求且不在睡眠時間，AI 已選擇待機行為。
- **When** 模擬 15 分鐘、期間觸發一次玩家互動，替換某個動畫資產。
- **Then** 至少出現 3 種有效自主行為；不每幀跳狀態；玩家互動只執行一次；任何行為都不永久卡住；Game Core 不引用 PNG 路徑。
- **證據**：behavior trace、事件圖、資產查表 log。

### TC-P0-12｜個性、喜好與成長分支
- **對應**：AC-GROW-01/02/03/04/05/07；FX-04；UT/IT。
- **Given** 兩隻同初始狀態、不同照顧歷程的寵物與固定 seed。
- **When** A 組偏玩耍探索、B 組偏休息陪伴，推進至成熟；分別給喜愛和不喜愛食物。
- **Then** 產生至少 2 種可重現成熟分歧；成長只前進、不跳階；行為、反應有差異；分歧紀錄附 `growth_reason`；外觀更換不重設核心資料。
- **證據**：growth record、rule ID、前後 state diff。

### TC-P0-13｜Debug 操作的可重現性
- **對應**：AC-GROW-06、AC-DEV-03/04/05/06/08；FX-01、FX-04；IT/E2E。
- **Given** 開發版開啟 Debug Panel，載入 5 組固定 fixture。
- **When** 改需求／個性、快轉 1h/24h/7d、設定 seed 並重播同一操作序列。
- **Then** Game Core、畫面與事件日誌同步；相同輸入事件得到相同成長與行為輸出；日誌包含 timestamp/event/old/new/reason。
- **證據**：Debug 操作錄影、重播測試 diff、事件匯出。

### TC-P0-14｜病痛提醒與恢復
- **對應**：AC-HEALTH-01..05；FX-09；UT/IT/E2E。
- **Given** 低健康且生病、背包有 1 份可用照護道具。
- **When** 顯示健康提醒、確認照護、快轉恢復期、存檔再重啟，並重送照護命令。
- **Then** 健康改善但不瞬間無條件滿血；`unwell→recovering→healthy` 按門檻轉換；只扣一次道具；狀態與原因可見且可恢復。
- **證據**：健康狀態機 trace、物品交易 log、錄影。

### TC-P0-15｜存檔完整性與版本遷移
- **對應**：AC-SAVE-01/02/04/05/06；FX-05；UT/IT。
- **Given** 有已照顧、已成長的 v1 存檔及一份舊 schema fixture。
- **When** 存檔關閉重啟，載入舊版本，並重送最近已完成的消耗交易。
- **Then** 六項需求、物品、性格、進化、時鐘一致；migration 不默默遺失欄位；不可重領；未知 schema 明確拒絕而非崩潰。
- **證據**：snapshot schema diff、migration log、單元測試。

### TC-P0-16｜存檔中斷／損壞回復
- **對應**：AC-SAVE-03、AC-DEV-08；FX-05；FI。
- **Given** 有最近一次完整主存檔與備份。
- **When** 在 0%、50%、99% 寫入進度強制截斷、重開，並嘗試載入壞 checksum。
- **Then** 能回到最近完整狀態；壞檔不會覆蓋有效備份；顯示可理解的恢復訊息。
- **證據**：fault-injection 紀錄、checksum 與 load report。

### TC-P0-17｜240×240 畫面及素材缺失
- **對應**：AC-UI-01..06；FX-01；E2E/UX。
- **Given** Mac 畫布 240×240、繁中完整字串集、其中一個 animation ID 對應圖檔不存在。
- **When** 在 2×/3×/4× 視窗操作所有 P0 畫面，替換 3 組 placeholder 資產。
- **Then** UI 不裁切、焦點不只靠顏色、缺圖用通用圖形；正常照顧不需聲音也看得懂；核心程式不需要為換圖改動。
- **證據**：視覺快照比對、字型覆蓋報告、測試錄影。

### TC-P0-18｜乾淨 Mac 的可執行交付
- **對應**：AC-DEV-01/07、AC-CLOUD-03/04/07；E2E/IT。
- **Given** 未安裝專案原始碼、但具有記錄之系統需求的 Apple Silicon 測試 Mac。
- **When** 從雲端成功建置的 Release 下載測試包、校驗 SHA-256、按照 README 開啟。
- **Then** 能啟動 240×240 模擬器並完成一次餵食／存檔；版本及 commit 可查；正式版無 Debug 快捷入口。
- **證據**：Release URI、SHA256、乾淨 Mac 螢幕錄影。

### TC-P0-19｜原始碼與核心跨平台隔離
- **對應**：AC-ARCH-01/03/04、AC-PLATFORM-01..04；UT/IT/FI。
- **Given** 同組錄製的命令／時鐘／seed 和 mock 的 Input/Display/Storage。
- **When** 分別換鍵盤映射與顯示驅動 mock，注入螢幕與儲存失敗。
- **Then** Game Core 結果相同且無 GPIO/SDL/HAL 依賴；錯誤能被觀察、處理；不得破壞合法存檔。
- **證據**：dependency scan、跨平台 state diff、故障日誌。

### TC-P0-20｜GitHub CI 與可重建性
- **對應**：AC-CLOUD-01/02/06/07/08；CI/SEC。
- **Given** 已授權 GitHub Repository，有明確 Rust toolchain/依賴鎖。
- **When** 提交正常 PR、再提交會造成測試失敗的 PR，對相同 tag 重新建置。
- **Then** 正常 PR checks 成功；失敗 PR 被阻擋；Release 可追蹤 commit SHA 且可重建；無金鑰或非授權素材洩露。
- **證據**：CI run URLs、PR status、掃描結果、重建 hash 記錄。

## 4. P1 驗收（生活內容）

### TC-P1-01｜物品購買、使用、存檔
- **對應**：AC-ITEM-01/03/04；FX-01；IT/E2E。
- **Given** 商店有合法售價與背包容量，玩家貨幣充足。
- **When** 用三鍵購買食物、使用一次、存檔重啟。
- **Then** 貨幣只扣一次售價；背包增 1 後減 1；效果僅觸發一次；存檔後一致。
- **證據**：交易流水、state diff、錄影。

### TC-P1-02｜交易失敗與未知物品
- **對應**：AC-ITEM-02/05；FX-06；IT/FI。
- **Given** 金額不足、背包滿、價格非法或存檔含未知 item_id。
- **When** 嘗試購買或載入未知物品。
- **Then** 失敗交易全部 rollback；貨幣不負數、物品不消失；未知物品走兼容提示而非 crash。
- **證據**：事務不變性報告、錯誤事件。

### TC-P1-03｜原創小遊戲
- **對應**：AC-GAME-01..04；E2E/UT。
- **Given** 一局固定種子的三鍵小遊戲與設定獎勵。
- **When** 正常完成、離開結果頁再回來，另測中途取消並重開。
- **Then** 正常完成只領一次貨幣；取消不領完成獎；計分在 10 次固定 seed 重現；全程不依賴觸控。
- **證據**：遊戲事件 log、獎勵 ledger。

### TC-P1-04｜房間、家具、喜好聯動
- **對應**：AC-ROOM-01/02/03/05；IT/E2E。
- **Given** 有兩個家具槽、可用家具與一個喜愛玩具。
- **When** 擺放適配家具、嘗試擺放不合適家具、讓 AI 自主活動，再存檔。
- **Then** 各槽唯一；錯誤放置不消耗道具；喜愛玩具改變 AI 行為評分；重啟擺設一致。
- **證據**：room state、behavior trace、錄影。

### TC-P1-05｜裝扮層與角色邏輯隔離
- **對應**：AC-ROOM-04、AC-UI-05；IT/E2E。
- **Given** 角色具有頭飾與服裝槽；有兩組佔位素材。
- **When** 裝備、卸除與更換配件。
- **Then** 預覽與角色圖層更新，主角個性和需求不重設；無相容配件提示，C 返回不丟資料。
- **證據**：render snapshot、character state diff。

### TC-P1-06｜臨時託管（候選）
- **對應**：AC-SITTER-01..04；IT/E2E。
- **Given** 託管功能被納入 M4，時段與保護機制已配置。
- **When** 正常開始→提前取消→重新開始→跨離線結束→重送結算。
- **Then** 需求變化按配置計算；開始/結束只計一次；不合法期間拒絕且顯示理由；重新載入可恢復。
- **證據**：託管事件、time trace、save diff。

## 5. P2 驗收（散步／DIY／好友）

### TC-P2-01｜沒有感測器也能驗證散步邏輯
- **對應**：AC-WALK-01/02；FX-10；UT/IT。
- **Given** Mac 模擬器的 MotionSource 回傳固定 0/100/1,000 步。
- **When** 依相同配置計算三組探索獎勵，再停用 MotionSource。
- **Then** 相同步數、seed、規則產生相同材料；沒有感測器時顯示「模擬模式／不可用」，不能顯示成實測步數。
- **證據**：步數注入 log、獎勵對照表。

### TC-P2-02｜實機計步有效性
- **對應**：AC-WALK-02、AC-ARCH-05/06；HW。
- **Given** 實體選定帶 IMU 的板卡與已固定的測試路徑／動作。
- **When** 靜置 10 分鐘、手持步行指定路線、搖晃模擬，分別記錄計數。
- **Then** 靜置不應持續虛增；相同模式可重複量測；誤差門檻應在 M5 感測器選型 ADR 中訂定，**未訂門檻不得標為已驗收**。
- **證據**：實機 sensor log、基準步數及誤差。

### TC-P2-03｜DIY 配方原子性
- **對應**：AC-WALK-03/04；IT/FI。
- **Given** 一份足量材料、一份不足材料與每日領取紀錄。
- **When** 合成成功、材料不足時嘗試，再把系統時鐘回撥。
- **Then** 成功一次性扣料並給成品；失敗全部 rollback；每日獎勵不會因回撥再發一次。
- **證據**：recipe ledger、前後背包 diff、clock anomaly。

### TC-P2-04｜兩台裝置配對與取消
- **對應**：AC-SOCIAL-01/03/04；HW/IT/SEC。
- **Given** 裝置 A/B 未配對，另有協定版本不符的模擬裝置 C。
- **When** A 提出配對但 B 拒絕；再次配對 B 確認；C 發送不相容封包。
- **Then** 拒絕時無好友紀錄；雙方確認才建立；不合法封包被忽略並記錄，不修改遊戲存檔。
- **證據**：兩端串口 log、配對畫面錄影。

### TC-P2-05｜交換道具重送與權限
- **對應**：AC-SOCIAL-02/04；FX-07；IT/SEC。
- **Given** 已配對裝置交換 ID=TX-0001 的道具，未配對第三台裝置存在。
- **When** 同一封包重送 10 次，第三台嘗試送狀態修改命令。
- **Then** 道具只轉移一次；未配對命令無效且不洩漏私密網路資訊。
- **證據**：封包 trace、交易流水、存檔 diff。

## 6. P3 驗收（線上世界）

### TC-P3-01｜離線保留核心玩法
- **對應**：AC-ONLINE-01/02；FX-08；IT/E2E。
- **Given** 首次安裝後已建立寵物，之後完全關閉網路。
- **When** 進行照顧、背包、房間、小遊戲並開啟線上入口。
- **Then** 離線功能正常，線上入口清楚說明不可用且可返回；不得無限 loading。
- **證據**：網路阻斷測試、錄影。

### TC-P3-02｜下載內容簽章／雜湊
- **對應**：AC-ONLINE-03；SEC/FI。
- **Given** 一份有效簽章內容包與經過一位元篡改的內容包。
- **When** 嘗試安裝兩份內容並觸發版本不相容包。
- **Then** 有效包可用；篡改與不相容包拒絕、不覆蓋舊內容；記錄錯誤並可返回。
- **證據**：簽章校驗、內容版本、回復 log。

### TC-P3-03｜更新失敗回復
- **對應**：AC-ONLINE-04；HW/FI。
- **Given** 已備份可啟動韌體與測試韌體更新包。
- **When** 在更新下載／寫入／重啟途中逐段模擬斷電或校驗失敗。
- **Then** 若支援 OTA，設備能恢復上一可用韌體且存檔不丟失；未通過不可發布 OTA 功能。
- **證據**：Flash 分割區、Boot log、斷電測試表。
