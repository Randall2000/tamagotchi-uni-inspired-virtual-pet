## 2. 像素規則

在 64×64 邏輯像素上檢查（圖檔每個邏輯像素是 2×2 同色區塊）。

| ID | 規則 | 為什麼 |
|---|---|---|
| PX-01 | 每個不透明像素都是色票 24 色之一 | 不出現色票外的混色 |
| PX-02 | 透明度只有 0／255，透明像素 RGB 為 0 | 沒有半透明邊與灰霧 |
| PX-03 | 同一材質內沒有孤立雜點：沒有同色鄰居、且被同材質另一色包圍（≥5／8）的像素不允許。眼睛與白色反光點除外 | 消除黑毛、白胸口的抖動雜點 |
| PX-04 | 輪廓沒有 1 格缺口（透明格被 ≥3 個不透明格包住），腳趾間距除外 | 輪廓階梯乾淨 |
| PX-05 | 實心區塊的外框一律是描邊色 `#1a0e17`；鬍鬚等 1 格細線保留原色 | 描邊一致，放在任何背景都清楚 |
| PX-06 | 道具色（水藍、飼料褐）不能零星出現在貓身上（≤3 格的小團） | 例如腳趾上的藍點 |
| PX-07 | 畫面上每個邏輯像素剛好對到整數個實體像素（2、3、4…），不會一格 2px、一格 3px | 邊緣粗細一致、瀏覽器不混色 |

## 3. 顯示（PX-07）

`motion.js` 的 `petPixelSizes(螢幕縮放, 螢幕密度)` 依裝置算出每個像素格要佔幾個實體像素（取整數），再反推角色顯示尺寸：

- 角色的「畫到的高度」（58 格）不超出房間高度；
- 能做到時幼貓比成貓小；若會讓幼貓縮到原設計 80% 以下，兩者同尺寸，成長只靠換圖表現；
- 畫面縮放或螢幕密度改變時重新計算。目前 `#room-scene` 的 `data-device-px-per-art-px` 會顯示「幼貓,成貓」的倍數，驗收時可直接看。

已知限制：螢幕密度 1 倍且視窗很窄時，只能選 1 或 2 倍，角色會偏小或偏大。手機與平板都是 2 倍以上，不受影響。

## 4. 重建流程

角色圖重新產生後，**最後一定要跑像素精修**，否則測試會失敗：

```bash
python3 scripts/remaster_kitten_pixels.py        # 需要時
python3 scripts/build-momo-action-preview.py     # 需要時
python3 scripts/pixel-polish.py                  # 必跑：套色票、去雜點、補缺口、統一描邊
python3 scripts/pixel-polish.py --check          # 應全部 0
npm test
```

`pixel-polish.py` 重跑結果不變（第二次 0 改動）。
