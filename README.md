# didi · 原創全彩電子寵物 MVP

這是一款原創、可在瀏覽器或 Mac 進行測試的全彩電子寵物。互動節奏參考 Tamagotchi Uni，但不使用 Bandai 角色、商標或產品素材；Catode32 只作開源技術研究參考。

公開 Preview：<https://tamagotchi-uni-inspired-virtual-pet.vercel.app>

## v0.10.1：自主日常行為與連續待機動畫

- 不按任何按鈕時，貓咪仍以 12 FPS 循環播放 `idle` 的 24 格畫面，而非 6–12 秒靜止等待。
- 每 3.5–6.5 秒穿插一次自主行為，包括實際散步、搖尾巴、舔毛、觀察及打呵欠等；連續兩次不重複同一類隨機行為。
- 行為播放時顯示對應提示，結束後回到持續待機；按下 A/B/C、進入選單、休眠、隱藏網頁時正確停止或恢復計時器。
- 日常行為是純視覺呈現，不會自動修改好感度、飽足、心情、清潔或精力。
- 遵守「只切換角色圖集影格」限制；散步的整體位移僅在角色真正走路時發生，沒有用整張圖晃動假裝有肢體動畫。
- 新增 Chrome 自主行為端對端測試：`python3 scripts/qa-momo-autonomous.py`。

## v0.10.0：19 組動作 × 幼貓與成貓

- 實際使用 `public/assets/momo-motions-preview/` 的 38 張 RGBA PNG 動畫圖集；各圖集 128×128 px/格、8 欄，依 16／24／32 格與 8／12 FPS 播放。
- 餵食、點心、喝水、清潔、玩耍、摸摸、如廁、睡前、睡眠、起床、探索與表情使用對應圖集，走路採逐格步態加實際位移。
- 動作只變換影格，不會用整張角色圖左右搖晃、旋轉、縮放來假裝動畫；幼貓和成貓的圖集獨立。年齡「成長中」仍使用幼貓圖像。
- **這批是重組預覽素材，不是 38 組人工精修的逐格動作**：部分影格重複，走路／睡覺等仍需逐像素審核；可參閱 [動作整合與素材限制](docs/MOMO_19_MOTION_INTEGRATION.md)。

## 網頁原型 v0.5：使用 4×4 Sprite Atlas 逐格角色動畫

- 240×240 全彩寵物畫面，**螢幕下緣固定六個不可點擊、僅供顯示選取狀態的功能圖示**：餵食、玩耍、清潔、睡覺／喚醒、狀態、選單。透過 A 移動選取，B 執行功能。一般照顧無須開主選單。
- 最右下角「選單」可經由 A/B 操作進入完整選單，提供其他互動、狀態及設定。螢幕所有選單項目皆不能觸控或滑鼠點擊，重設必須由按鍵確認。完整選單的主要照顧動作不再有額外分類層級。
- A/B/C 三個實體形式按鍵仍可用：A 在六項功能或選單內輪選，B 確認，C 返回／取消正在播放的動作。鍵盤 A/B/C 或 J/K/L 也能操作。
- 餵食、玩耍、清潔、休息與喚醒使用 **4×4、共 16 格原創像素角色圖集**和確定性的時間軸。第 1 排用於待機眨眼、第 2 排進食、第 3 排洗臉、第 4 排玩毛線球。校正各影格在圖格中的像素偏差，角色腳底與中心保持固定；動作不會搖晃、旋轉、放大或縮小。角色只會因永久累積的好感度跨越成長門檻而變大，且不會退回較小階段。
- 成長由永久好感度決定：幼年 0–9、成長中 10–29、成年 30+。餵食／清潔／梳理各 +1，玩耍／摸摸各 +2；時間流逝與飽足、心情等需求衰減不影響好感。狀態頁顯示目前好感與下一階段門檻。
- 畫面仍然不能觸控；按鈕操作時中斷待機眨眼以避免計時器干擾，照顧動畫播放中暫時停用重複操作以防連點。
- 沿用既有瀏覽器本機存檔 key，保留 v0.2 已有的玩家進度；補上清潔數值（舊存檔缺少時採初始值）。狀態頁直接顯示主要數值。

## 已知限制

- 這一版是 **Web 互動原型**，角色現在按 4×4 Sprite Sheet 影格順序播放；成長尺寸固定於各階段，素材尚未提供不同成長外觀。
- 尚未完成健康、個性 AI、成長分歧、物品背包、真實睡眠排程、完整離線推進與帶版本的存檔遷移。
- Web 的遊戲邏輯仍是 JavaScript，與 Rust 遊戲核心尚未完全共用；這一版只保留了操作邊界，不應將兩端視為相同遊戲規則。
- 尚無可燒錄 ESP32 韌體、原生 macOS app、雲端玩家存檔或完整板卡適配驗收。
- 上傳圖集沒有完整的睡姿、伸懶腰或望窗外動作；這些情境只暫用現有眨眼或舉爪影格，不以整張圖的形變假裝有新動作。未來需要補畫對應影格。

## 技術結構

- app.js：Web 模擬器、存檔、主畫面及動作狀態協調。
- navigation.js：A/B/C 獨立導覽狀態機；主畫面與完整選單都只能透過按鍵變更。
- motion.js：固定四列十六格的影格時間軸與 atlas 坐標，獨立於遊戲數值。
- pet.js：目前 Web prototype 的暫時養成數值。
- firmware/：硬體無關的 Rust game-core、game-app、platform-api 骨架，尚非韌體映像。
- docs/：[PRD.md](docs/PRD.md) 產品規則、[BALANCE.md](docs/BALANCE.md) 所有數值、[ACCEPTANCE_WEB.md](docs/ACCEPTANCE_WEB.md) Web 驗收清單、[ACCEPTANCE_MAC_HW.md](docs/ACCEPTANCE_MAC_HW.md) Mac／實機驗收；舊版 v1.1 在 docs/archive/（不要用來驗收）。
- .github/workflows/ci.yml：Node 回歸測試與 Web 原型壓縮包。

## 本機執行

Apple Silicon Mac 可使用 Node 20+，無須外部 Node 套件，於專案目錄執行：

    npm test
    npm run serve

開啟 <http://localhost:4173>。本機伺服器只提供網頁本身與 `public/assets/` 圖檔，不會送出 `.env.local`、`.git` 等專案檔案。

## 上雲

Vercel 已連結 GitHub `main`：推上 `main` 就會自動重新部署 Preview。一鍵上傳：

    npm run ship -- "這次改了什麼"

會先跑測試，沒過就不上傳；通過才 commit 並 push。

目前沒有 Rust 編譯驗證證據；在本機環境中尚未安裝 cargo / rustc。
